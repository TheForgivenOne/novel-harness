# novel-harness — Specification

Living spec. Source of truth for design decisions. Update alongside code.

## 1. What this is

`novel-harness` is an installable Bun/TypeScript CLI (package `novel-harness`,
command `novel`) that manages a novel as an **OKF v0.2 knowledge bundle** and
renders **agent adapters** so coding agents (Claude Code, opencode, Codex,
Gemini CLI) can write the novel natively.

Principles:

- No MCP. No runtime service. Plain files.
- The CLI never calls an LLM. It scaffolds, validates, packs context, and
  builds. All reasoning happens in the user's agent.
- The bundle is a portable OKF v0.2 directory. The CLI is optional tooling,
  never required to read the bundle.

Reference: [OKF v0.2 spec](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md).

## 2. Project layout

```
<project>/
  story/                # the OKF bundle (portable, self-contained)
  .novel/
    config.json         # bundle path, targets, author actor, build options
    workflows/          # optional per-project workflow overrides
    manifest.json       # tracks CLI-generated files (idempotent sync)
  dist/                 # manuscript build output (gitignored by template)
```

## 3. Bundle layout

```
story/
  index.md              # okf_version: "0.2" + grouped nav (CLI-generated)
  log.md                # chronological change history (CLI-written)
  novel.md              # type: Novel
  plan.md               # type: Plan — agreed premise, cast, rules, divergence goals, decision log
  knowledge.md          # type: Knowledge — who knows what, when, per season
  outline.md            # type: Outline — structure + scene tables, # Next
  characters/           # Character
  locations/            # Location
  factions/             # Faction
  world/                # Worldbuilding
  plot/                 # Plot Thread
  themes/               # Theme
  relationships/        # Relationship
  timeline/             # Timeline Event
  chapters/
    ch-01.md            # type: Chapter
    ch-01/outline.md    # type: Chapter Outline — intent, beats, notes
    ch-01/scenes/
      sc-01.md          # type: Scene (prose in body)
  references/           # Reference
  research/             # Research Note
```

`index.md` and `log.md` are reserved filenames (OKF §3.1) at every level and
are never concept documents. `index.md` files are generated by the CLI and
committed. The bundle-root `index.md` carries `okf_version: "0.2"`. `log.md`
date headings must be ISO `YYYY-MM-DD` (error `okf/log-date` otherwise).

## 4. Concept types

`type` is the only OKF-mandatory frontmatter key. The catalog below is the
harness profile; missing **Required** fields are hard validation errors.

| Type | Home | Required (profile) | Notable optional |
|---|---|---|---|
| `Novel` | `novel.md` | `title` | genre, pov, tense, themes, fandom, source_works, canon_type |
| `Plan` | `plan.md` | `title` | status, generated |
| `Knowledge` | `knowledge.md` | `title` | status, generated |
| `Outline` | `outline.md` | `title` | status, generated |
| `Character` | `characters/` | `title`, `role`, `fate` | aliases, affiliations, relationships |
| `Location` | `locations/` | `title` | region, status |
| `Faction` | `factions/` | `title` | goals, alignment |
| `Worldbuilding` | `world/` | `title`, `category` | category ∈ magic/tech/culture/geography |
| `Item` | `items/` | `title` | class, owner |
| `Plot Thread` | `plot/` | `title`, `status` | kind (main/sub), stakes, participants |
| `Arc` | `arcs/` | `title` | season, episodes |
| `Episode` | `episodes/` | `title`, `sequence` | arc, air date |
| `Chapter` | `chapters/` | `title`, `sequence`, `pov` | status, words |
| `Chapter Outline` | `chapters/` | `title` | status, generated |
| `Scene` | `chapters/<chapter>/scenes/` | `title`, `sequence`, `pov` | location, cast, status, when |
| `Timeline Event` | `timeline/` | `title`, `sequence`, `when` | participants, location, arc, episode |
| `Theme` | `themes/` | `title` | |
| `Relationship` | `relationships/` | `characters` (exactly 2 links), `kind` | status |
| `Reference` | `references/` | `title`, `resource` | |
| `Research Note` | `research/` | `title` | question, sources |

Shared optional (OKF families): `description`, `tags`, `sources`,
`verified`. Required on narrative types (Novel, Plan, Knowledge, Outline,
Character, Plot Thread, Chapter, Chapter Outline, Scene, Timeline Event):
`status`, `generated`.

`plan.md` and `knowledge.md` are singleton concepts like `novel.md` (one file
at a fixed path; `novel new plan` / `novel new knowledge` overwrite them).
`plan.md` is the frozen agreement — premise, cast, rules, divergence goals,
and a dated `# Decisions` log that the `/outline` workflow writes into before
creating concepts. `knowledge.md` is the live "who knows what, when" matrix,
one section per season, updated before drafting and after every reveal; scenes
are written from the POV character's knowledge, never the audience's.

`outline.md` is a third singleton: the story spine. `# Structure` holds one
row per chapter (Arc | Chapter | Sequence | POV | When | Words), `# Scenes`
one row per scene (Chapter | Scene | Sequence | POV | When | Status), and
`# Next` names the scene to draft first. Per chapter, `chapters/<slug>/outline.md`
(`Chapter Outline`) carries `# Intent`, a `# Scenes` beat table, `# Story So Far`,
`# Canon Refs`, `# Notes`, and `# Open Questions`. Scenes are canonical under
`chapters/<slug>/scenes/` (legacy `chapters/<slug>/<scene>.md` still parses).
`novel new scene` refuses to create a scene whose row is missing from the
outline (AC1); `novel outline --check` reports drift between rows and files
(AC2); `/draft` and `/continuity` keep rows, statuses, and the knowledge
matrix in sync.

Validation also warns when two concepts of the same type share a normalized
title or alias (`profile/duplicate-concept`); merge them and record alternate
names in `aliases` rather than forking the entity. It warns
(`profile/missing-tags`) when a query-critical concept carries no tags, and
(`profile/orphan-chapter`) when a Chapter has no scenes — canon season data
belongs in an `Arc` under `arcs/`, never in `chapters/`. Timeline Events whose
`when` parses to a date that sorts before an earlier-sequence event's date
warn (`profile/sequence-when`); partial dates are only compared on components
both sides define.

## 5. Field semantics

- `status` — OKF lifecycle repurposed as **canon state**:
  `draft` = tentative, `stable` = canon, `deprecated` = cut but kept.
  Absent ⇒ `stable` (OKF §5.4).
- `fate` — a Character's life-state: `alive | dead | unknown`.
  Separate from `status` because `status` is canon, not mortality.
- `dies_in` — a Character's death scene as a bundle link. Required for
  deterministic ordering whenever `fate: dead`; without it the checker can
  only warn (`continuity/unverifiable-death`).
- `origin` — where a fact comes from: `source` (from the original work; cite
  it in `sources`), `fanon` (invented here), `divergent` (changed from source
  canon; requires `diverges_at`).
- `diverges_at` — bundle link to the Scene or Timeline Event where this story
  departs from source canon.
- `divergence` — on Timeline Events, the fic's relationship to the canon
  event: `intact` (happened as canon; implicit for `origin: source`),
  `altered` (happened, but changed), `averted` (never happened), `added`
  (fanon event). `altered` and `averted` require `diverges_at`; `added`
  should be `origin: fanon`. This is the divergence ledger: what your story
  changed, and where.
- `when` — in-world date. Required on Timeline Event; optional on Scene, where
  it makes `novel context` pull the canon events happening on that date.
- `arc` / `episode` — links on a Timeline Event to the Arc and Episode it
  belongs to.
- `tags` — pushed hard: `novel query tag`, `timeline --tag`, and search all
  key off them. Tag season or arc (`season-3a`), species, pack, region, role.
- `words` — a Chapter's drafting range, `{ min, max }`: positive integers,
  either bound optional, `min <= max`. Chapter words are the summed scene
  bodies under `chapters/<chapter>/` — the same directory association the
  manuscript builder uses, so validate, stats, and build always agree.
  Malformed ranges are errors (`profile/words`); written prose outside the
  range warns (`profile/word-count`) unless the chapter is `draft` or
  `deprecated`. The range is a drafting target, not a gate: warnings never
  change the validate exit code. `novel query stats` reports each chapter's
  bounds and state, and `/draft` and `/continue` budget remaining scenes
  against what is left of the range.
- `refs` — web references for detail on demand:
  `[{ title, url, kind }]` where kind ∈ `transcript | recap | wiki |
  interview | other`. Recon maps rather than extracts: concepts hold
  medium-depth documentation, and `refs` point at the authoritative pages a
  later agent fetches when it needs exact staging, voice, or dialogue.
  `novel context` renders them as "Web references (fetch for detail)" and
  `novel query refs <concept>` lists them.
- `fandom`, `source_works`, `canon_type` — fanfiction metadata on the Novel;
  `source_works` is a link list to `Reference` concepts.
- `sequence` — sort order, scoped per parent. Chapters restart scene
  numbering; build sorts chapters then scenes.
- `generated` — `{ by, at }`, actor convention (OKF §7):
  `human:<id>`, `<producer>/<version>`, `process:<id>`.
- `verified` — list of `{ by, at }`; a `human:` verifier means the author
  signed off. Absence means unverified.
- `sources` — OKF §5.1 provenance, with optional credibility signals.
- Timestamps (`generated.at`, `verified[].at`, `stale_after`) must be ISO
  8601 datetimes with an explicit UTC offset; date-only or offset-less
  values are errors (OKF §5).
- Links use bundle-relative form `/characters/elena-voss.md` (OKF recommends
  absolute form, §6.1). Relative body links and relative
  `sources[].resource` paths are also valid: they resolve against the
  concept's own directory (OKF §6.2).

## 6. Continuity mechanics

Per-scene `cast` is the working layer: a list of character links appearing
in the scene. Deterministic checks order scenes by
`(chapter.sequence, scene.sequence)` and flag:

- a cast member appearing after the scene named by their `dies_in`;
- a `fate: dead` character with no `dies_in` (warning; order unverifiable);
- a POV character not listed in `cast`;
- missing or duplicate `sequence` values among siblings;
- broken links, bundle-absolute or relative (warning; OKF tolerates them);
- `status: stable` scenes referencing `status: draft` canon (warning).

Scene-to-scene knowledge diffs are an LLM pass delivered as the
`/continuity` workflow, not a CLI feature.

## 7. Fanfiction

Source canon enters the bundle as `Reference` concepts under `references/`
(one per source work). `novel.md` carries `fandom`, `source_works` (links to
those references), and `canon_type` ∈ `canon-compliant | canon-divergent |
alternate-universe | fusion | crossover`. `canon-compliant` and
`canon-divergent` require at least one `source_works` link.

Recon is **web-first**: the agent must read sources with web tools and cite
the exact page for each fact. If it has no web tools it must stop rather than
reconstruct canon from model memory. Unsourced facts are not canon. This
keeps a fic faithful to the source instead of to the model's recollection.
Author-provided material is a source too, but it must be saved into the
bundle first (a Reference concept or a file under `references/`) and cited
as a file; citing an unfollowable string is reported as
`fanfic/unverifiable-source`.
`novel new reference "<work>" --resource <url> --source-work` creates the
Reference and attaches it to `source_works` in one step.

One entity is one concept. Recon searches existing titles and aliases before
creating, merges duplicates, and records alternate names in `aliases`. A duo
is two Character concepts plus a Relationship concept, never a merged
character file.

Recon follows a hybrid web/state model:

- **Bundle = state.** Characters, locations, factions, worldbuilding, items,
  arcs, episodes, timeline, and relationships hold medium-depth documentation
  — enough to plan, outline, and fact-check without a network.
- **Web = detail.** Every concept carries `refs` to its authoritative pages.
  An Episode's body holds a compact scene-by-scene `# Recap`; its transcript
  stays on the web behind `refs`. Long or verbatim material is never pasted
  into the bundle.
- **Voice stays local and cited.** Recon writes
  `references/voice-<work>.md` (a Reference) covering POV, register, verbal
  tics, slang, and how the work handles banter and exposition.
- **Writers fetch on demand.** `/draft` and `/weave` read the recap and voice
  locally, fetch `refs` transcripts when a scene needs exact choreography or
  dialogue feel, and match beats and voice without copying long passages.

Every fact can declare its `origin`:

- `source` — imported from the original work. SHOULD cite the work in
  `sources` and attribute claims with footnotes keyed to `sources[].id`
  (OKF §5.1). A missing citation is a warning.
- `fanon` — invented for this story.
- `divergent` — changed from source canon. MUST set `diverges_at` to the
  Scene or Timeline Event where the change happens. Missing `diverges_at` is
  an error.

`sources[].resource` may be a bundle-relative path; unresolved paths warn
(`fanfic/unresolved-source`). `source_works` must point at `Reference`
concepts and `diverges_at` at a Scene or Timeline Event; other targets warn.
`source_works` and `diverges_at` are traversed by `novel context` and
`novel graph` like any other link. `novel new` accepts `--origin`,
`--diverges-at`, `--fandom`, `--canon-type`, and `--source-works`;
`novel init` accepts `--fandom` and `--canon-type`.

The fanfiction loop is three-phase: `/recon` learns the source broadly and
records it as `origin: source` concepts with citations, `/outline` plans
against that baseline and marks deliberate divergences with `diverges_at`,
then `/draft` writes.

The `/continuity` workflow audits contradictions against `origin: source`
concepts that are not marked `origin: divergent`.

### Canon packs

One crawl should serve many fics. A **canon pack** is a portable OKF bundle
containing every `origin: source` concept plus all of `references/`, with a
`pack.json` manifest (name, fandom, source works, export date, concept
count). `novel canon export [--out <dir>]` writes one, defaulting to
`canon/<fandom>/` in the project; `novel canon import <dir> [--force]` copies
it into `story/`, preserving paths so bundle-relative links keep working.

Import outcomes: identical → skipped; local `fanon` or `divergent` → kept
local; both sides `source` and different → conflict unless `--force`. Every
outcome is reported. `.novel/canon.json` records imported packs.
`novel query ... --bundle <dir>` queries a pack directly.

### Incremental recon

`novel query stale [--days N]` lists `origin: source` concepts whose
`stale_after` has passed or that have not been refreshed in N days (default
30); validation warns `profile/stale`. `/recon` runs in **update mode** when
canon already exists: refresh only the stale concepts from their `refs`, bump
`generated`, set a fresh `stale_after`, and never touch author-owned
concepts.

### Divergence ledger

`novel query divergences [--status altered]` groups Timeline Events by their
relationship to canon: `altered`, `averted`, `added`, `unmarked` (fanon events
with no status), and `intact`. This is the "what changed vs canon" report:
which beats were supposed to happen but did not, which happened differently
because of the MC or fanon, and which exist only in this fic.

`altered` and `averted` events MUST set `diverges_at` to the scene that
changes or prevents them (error `fanfic/divergence-without-scene`); `intact`
with a `diverges_at` warns (`fanfic/intact-with-divergence`); `added` marked
`origin: source` warns (`fanfic/added-but-source`). `novel query timeline` and
`novel query when` surface the status, and `/outline` writes the ledger,
`/draft` and `/weave` honor it, and `/continuity` audits it.

## 8. CLI surface

| Command | Does |
|---|---|
| `novel init [dir]` | Scaffold project: `story/` bundle, `.novel/config.json`, adapters |
| `novel new <type> [name]` | Create a concept at the correct path with template + frontmatter (`--from-template`); scenes take `--chapter <id\|title\|slug>` |
| `novel import <file>` | Bulk-create concepts from a CSV or YAML list (atomic, one index pass) |
| `novel set <concept> f=v...` | Update frontmatter fields with link and enum resolution (`--unset`, `--at`, `--dry-run`) |
| `novel rm <concept>` | Remove a concept; refuses when other concepts link to it (`--force`) |
| `novel mv <scene> --to <chapter>` | Move a scene between chapters and rewrite every link to its new id |
| `novel mv <chapter> --to <slug>` | Move a chapter and its whole folder (`outline.md`, `scenes/`), rewriting links |
| `novel outline [--check]` | Print `story/outline.md`; `--check` reports drift between outline rows and bundle files and exits 1 on hard drift |
| `novel status` | Per-chapter progress: drafted vs stub scenes, word counts, budget, and the next scene to draft |
| `novel renumber [--type <list>] [--start <n>] [--step <n>] [--sort sequence\|when] [--dry-run]` | Compact sequence numbers: one run for Chapters and Timeline Events, one per chapter for Scenes; `--sort when` orders Timeline Events by their `when` date (unparseable dates last) instead of their current sequence |
| `novel rename <concept> <name>` | Rename a concept and rewrite every link to it |
| `novel convert <from> <to>` | Convert concepts between types and relocate them (`--file`) |
| `novel merge <primary> <other>` | Merge a duplicate into the primary (preview; `--yes` applies) |
| `novel tag --batch <rules.yaml>` | Apply YAML match/add tagging rules |
| `novel context [<concept> | --story] [--so-far]` | Print the bundle slice for an agent (stdout); `--story` prints the whole-story slice, `--so-far` appends who-knows-what reader state for a scene |
| `novel query <subcommand>` | Deterministic reads: `search`, `timeline`, `when`, `divergences`, `stale`, `character`, `at`, `tag`, `refs`, `stats [--summary]`, `threads [--dangling]`; `--json`, `--bundle` |
| `novel canon <export\|import>` | Move canon between projects as a reusable pack |
| `novel validate [--fix] [--only <id\|glob>] [--severity error\|warning] [--quiet] [--summary] [--json]` | OKF v0.2 conformance + strict profile checks; `--fix` regenerates indexes and applies safe quick fixes; filters limit printed diagnostics while the exit code still reflects the whole bundle |
| `novel audit [--fix] [--receipts] [--online] [--only <id\|glob>] [--severity <level>] [--quiet] [--summary] [--json]` | One report: project drift, content diagnostics, source classification, receipts, link liveness |
| `novel fetch <url>` | Fetch a page and append a sha256 receipt to `.novel/fetch-log.jsonl` (`--max-bytes`) |
| `novel doctor [--fix]` | Report or fix config, structure, adapters, and index drift |
| `novel migrate [--spec <rules.yaml>]` | Mechanical upgrade; with `--spec`, also run convert/merge/tag migrations |
| `novel index` | Regenerate all `index.md` files |
| `novel build [--out]` | Assemble manuscript in sequence order into `dist/` |
| `novel export [--format md\|html]` | Export the manuscript (epub/pdf not yet supported) |
| `novel diff [ref1] [ref2]` | Git diff of bundle concepts, working tree by default |
| `novel sync` | Render adapters; idempotent via `.novel/manifest.json` |
| `novel graph [--html]` | Relationship graph as JSON or self-contained HTML |

Style: flat verbs. `new` rejects unknown types and prints the catalog. Every
command answers `novel <command> --help` with usage, flags, and examples.

Bulk authoring: `novel import <file>` accepts a CSV (header row) or a YAML
list and validates every row before writing anything; sequences stay
continuous across rows, duplicates are skipped, and the entire batch is one
load, one index pass, and one log entry. Rows accept the same fields as
`novel new` plus `fate`, `aliases`, and `sequence`; unknown scalar columns
become frontmatter. `novel set` updates fields in place with link, enum, and
sequence handling; `novel rm` refuses to orphan inbound links unless
`--force`; `novel mv` relocates a scene and rewrites links because its
concept id changes.

`novel query` emits deterministic, LLM-free reads over the bundle:
`search <text>` (titles, aliases, ids, tags, descriptions, bodies; ranked,
with snippets and optional `--type`, `--tag`, and `--limit` filters),
`timeline [--tag <tag>] [--on <date>] [--from <when>] [--to <when>]` in
sequence order, `when <date|event>` (a canon snapshot: event body,
participants, location, arc, episode, and neighbouring events),
`divergences [--status <status>]` (the canon divergence ledger),
`stale [--days <n>]` (canon due for a refresh),
`character <name>` (scenes in manuscript order, timeline events,
relationships, affiliations, locations), `at <location>` (scenes in
manuscript order), `tag <tag>` grouped by type, and `refs <concept>` (web
references to fetch), and `stats` (bundle health: manuscript word counts and
per-chapter breakdown including word-target state, concepts by type,
characters by `fate`, tags, sources, divergence, stale canon), and `threads
[--dangling]` (plot threads and the scenes that advance them; `--dangling`
lists only threads no scene references). Every subcommand accepts `--json`, which
is what the `/query` workflow consumes, and `--bundle <dir>` to query any
bundle (for example a canon pack) without an open project.

Content operations are link-aware and log-writing: `rename` rewrites every
bundle-relative link, `convert` retypes and relocates (refusing
scene-bearing chapters), `merge` folds a duplicate into a primary (preview
unless `--yes`; merges aliases, tags, sources, and body), `tag --batch`
applies YAML match/add rules, and `audit` classifies every
`sources[].resource` and unquotes quoted URLs with `--fix`. `new
--from-template <name>` prefills a concept from `.novel/templates/<name>.md`.
`diff [ref1] [ref2]` compares bundle state — working tree by default,
including untracked concepts — and annotates origin and divergence.

Dates are matched by the most specific component given: `--on 2011` matches
any 2011 event, `--on "November 2011"` that month, `--on "2011-01-09"` that
day. The parser accepts ISO dates and freeform in-world dates like
"January 9, 2011" and "9 January 2011".

## 9. Adapters

One canonical workflow definition (name, description, argument hint, prompt
body) is rendered per target:

| Target | Instructions | Commands | Agents | Skills | Tools | Hooks |
|---|---|---|---|---|---|---|
| Claude Code | `CLAUDE.md` | `.claude/commands/<name>.md` | `.claude/agents/<name>.md` | `.claude/skills/<name>/SKILL.md` | — | deferred |
| opencode | `AGENTS.md` | `.opencode/command/<name>.md` | `.opencode/agent/<name>.md` | `.opencode/skill/<name>/SKILL.md` | `.opencode/tools/<name>.ts` | `.opencode/plugin/novel-guard.ts` |
| Codex / generic | `AGENTS.md` | — | — | — | — | — |
| Gemini CLI | `GEMINI.md` | `.gemini/commands/<name>.toml` | — | — | — | deferred |

`AGENTS.md` is shared by opencode and Codex: one file serves both. The
`agents-md` and `opencode` adapters must render it byte-identically (shared
notes in `src/core/adapters/notes.ts`); sync errors on any other collision.

Claude Code renders the workflow commands as before and also receives the
package skills (`.claude/skills/`). opencode is the full target: agents,
skills, tools, and the guard plugin. Gemini keeps instructions + commands;
Codex receives instructions via `AGENTS.md` (no commands). Gemini extensions
and Claude hooks are invasive user-owned configuration and are deferred.

Arguments: canonical workflow bodies use `{{args}}`. Claude and opencode
render it as `$ARGUMENTS`; Gemini keeps `{{args}}`.

Renderer backends: markdown+frontmatter (Claude, opencode agents/skills),
TOML (Gemini), TypeScript tools and plugins (opencode), plus a shared
instructions renderer with per-agent notes.

Generated files carry a `generated by novel-harness — do not edit` header
and are tracked in `.novel/manifest.json`. `sync` overwrites only tracked
files; a tracked file modified by a human is reported, not clobbered.

All four targets are enabled by default at init.

### Artifact kit

The package ships opinionated artifacts, rendered per target capability:

- **Agents** (opencode, Claude): `researcher` (web-only subagent; edit/
  write denied), `skeptic` (read-only verification of `origin: source`
  claims against their refs), `continuity-checker` (read-only audit).
- **Skills** (opencode, Claude): `novel-harness` (bundle model and CLI
  cheatsheet), `novel-recon` (attested / inferred / unknown discipline,
  citations), `novel-drafting` (canon rules, divergence, word budgets),
  `novel-fanfic` (source/fanon/divergent semantics), `novel-migration`.
- **Tools** (opencode): `novel_query`, `novel_context`, `novel_validate`
  (typed wrappers over the CLI; queries return JSON, context returns the
  context markdown, validate returns diagnostics text), and `novel_fetch`, which
  fetches a page, appends a `{url, fetched_at, sha256, bytes}` receipt to
  `.novel/fetch-log.jsonl`, and returns the text. The receipt log is the
  evidence trail recon guardrails are checked against.
- **Plugin** (opencode): `novel-guard.ts` runs `novel validate` after
  writes/edits under `story/` and appends the tail of the diagnostics to
  the tool result, persisting `.novel/last-validate.json` each time. It
  reports, never blocks — blocking gates are a later pass once the noise
  level is known.

Validator gates over the evidence trail (`source-without-refs`,
`unverified-source`, receipt coverage in `audit`) are deferred to
the guardrail pass that follows dogfooding.

## 10. Workflows

Canonical workflows ship with the package; a project may override any of
them in `.novel/workflows/<name>.md`. v1 set:

`/recon`, `/outline`, `/draft`, `/weave`, `/continue`, `/revise`,
`/continuity`, `/query`, `/ask`, `/migrate`, `/skeptic`.

`/recon` records canon through the artifact kit: broad crawling is delegated
to the `researcher` subagent, each fact is fetched with `novel_fetch` so it
leaves a receipt in `.novel/fetch-log.jsonl`, and canon is not declared
complete until the `/skeptic` pass has checked `origin: source` claims
against their refs. `/skeptic` also runs standalone on any concept.
Receipt-backed recon needs the opencode tool target; on targets without
tools the researcher/skeptic discipline still applies and citations fall
back to URLs in `refs`.

Fanfiction runs them in three phases: `/recon` records source canon as
`origin: source` concepts with citations, `/outline` plans against that
baseline and marks divergences, then `/draft` writes. `/draft` and `/weave`
use `novel query when` so a scene set on a canon date keeps the canon beats
and recorded dialogue intact while the MC is woven in.

Planning is gated on the plan document. `/outline` reads `story/plan.md`
first and stops if it is still the init template: it extracts the premise,
cast, rules, and divergence goals from the author, freezes each decision
into `plan.md` under `# Decisions` (confirm-back: restate in one line, wait
for a yes, never guess), and gets approval before bulk-creating scene stubs.
Before drafting begins it fills `story/knowledge.md` — a per-season "who
knows what, when" matrix covering the secret, knowledge about the MC, and
knowledge between characters, each row with `since` and how they learned it.

Planning is also gated on the outline layers: `/outline` writes
`story/outline.md` (`# Structure` and `# Scenes` rows plus `# Next`) and one
`chapters/<slug>/outline.md` per chapter (intent, beats, story-so-far, canon
refs, notes) **before any scene file exists**. `novel new scene` hard-errors
when the story outline exists but has no row for the chapter or scene, so a
scene file can never precede its plan (AC1). `novel outline --check` keeps
rows and files in sync, and `novel status` answers "what do I draft next,
from whose POV, with what budget" from the bundle alone (AC2).

`/draft` starts where `# Next` points, writes from the POV character's
knowledge (never the audience's), and after each scene flips its `# Scenes`
status (`stub` → `drafted` → `revised`), marks the beat done in the chapter
outline, refreshes `# Story So Far`, and advances `# Next`. `/continuity`
cross-checks chapter outline state against the scenes and the knowledge
matrix.

`/recon` gates on receipts: after the skeptic pass, `novel audit --receipts`
must pass so every cited URL has a `.novel/fetch-log.jsonl` receipt, and key
dated facts (debuts, deaths, plot mechanics) are inlined into timeline
concepts rather than deferred to an author placeholder.

`/draft` writes from the POV character's knowledge, not the audience's:
it reads `story/plan.md`, `story/outline.md` (starting where `# Next`
points), and `story/knowledge.md` before the scene, and updates the matrix
and the outline rows after any reveal. `/continuity` audits the matrix —
every recorded reveal must still hold and every scene reveal must be
recorded.

`/draft` and `/continue` read a Chapter's `words` range and the words already
written, then size the remaining scenes so the chapter lands inside it. A
range that cannot be met without padding is a signal to add a scene stub, not
to bloat one; chapters without `words` keep the 800-word floor guidance, and
`/outline` proposes a range when it stubs chapters.

Prompts are CLI-first (call `novel context`, `novel validate`) and restate
file conventions so an agent can proceed if the CLI is absent.

## 11. Config

`.novel/config.json`:

```json
{
  "version": 1,
  "bundle": "story",
  "targets": ["agents-md", "claude", "opencode", "gemini"],
  "author": "human:author",
  "build": { "out": "dist", "format": "markdown" }
}
```

`version` is the config schema version. A config without one loads as
`version: 0` (legacy). `novel doctor` reports a stale version; `novel doctor
--fix` writes the current one.

### Migration

`novel doctor` is a read-only report: config version, missing concept
directories, stale or missing adapters, adapter conflicts, index drift, and
content diagnostics grouped by code. `novel doctor --fix` applies only
mechanical fixes — config version, missing directories with placeholder
indexes, regenerated indexes, and re-rendered adapters. It never auto-fixes
content.

Content migrations are agent-driven through the `/migrate` workflow, which
uses `novel validate` as its checklist: convert seasons recorded as Chapters
into `Arc`s under `arcs/`, add tags, capture author-provided material as
bundle files, and merge duplicate concepts into one with `aliases`.

`novel migrate` is the entry point for an old project: it runs the mechanical
fixes (equivalent to `novel doctor --fix`), renders the `/migrate` agent
command, prints the remaining content diagnostics, and tells the author to
restart their agent and run `/migrate`. This avoids the chicken-and-egg where
the migration command does not exist until the project is migrated.

`novel migrate --spec <rules.yaml>` runs content transformations after the
mechanical fixes. The spec is a YAML list of actions executed in order:
`convert` (`from`/`to` type slugs, optional `file`), `merge`
(`primary`/`remove`), and `tag` (a `match` mapping plus an `add` list). The
whole spec is validated before anything runs; a failing action reports its
index and leaves earlier writes in place.

`novel validate --fix` applies unambiguous quick fixes in addition to
regenerating indexes: quoted source resources are unquoted, and Timeline
Events with `divergence: added` and no `origin` get `origin: fanon`.
Everything semantic — tagging without a rule, merging duplicates, unresolved
sources, broken links — is still reported, never guessed.

## 12. Testing

`bun test`. Fixture bundles under `tests/fixtures/`. Golden files for
adapter output and validator messages. `bun run typecheck` (strict TS) must
pass.

### 2026-09-14 — Test suite restructure

The test suite grew organically (flat file names, mega-files, no snapshot

with a documented conventions file (`tests/README.md`), a golden updater
(`bun run test:update`), a coverage script (`bun run test:coverage`, bar

coverage, structure) are all available on `bun:test`.

### 2026-09-21 — Original fiction is the primary focus

Reframes the 2026-09-12 decision that made fanfiction "first-class" as the
project's identity. Fanfiction stays **fully supported**; it is no longer the
headline.

- **Original novels and series are the primary use case.** The pitch is a
  series bible and manuscript in one validated OKF bundle, with mechanical
  continuity checking across books.
- **Fanfiction remains fully supported** — `origin`, `diverges_at`,
  `canon_type`, canon packs, and the `/recon → /outline → /draft` loop are
  unchanged. No fanfic capability is removed.
- **Rationale:** framing the tool as a fanfic tool caps the market and reads as
  a toy to professional writers. The underlying features (timeline, continuity
  audit, source/divergence tracking) are series-bible features that serve both.
- **No original-fiction work is blocked for fanfic's sake**, and vice versa.
  The positioning document is `README.md`; the roadmap ordering is unchanged.
