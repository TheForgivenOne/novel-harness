# Trademark Policy

"novel-harness", the `novel` command name, and the project logo are trademarks
of the maintainer. This policy explains what that means for the code license,
forks, and the community.

## The code license (MIT) and the name are separate

The [MIT license](LICENSE) grants you broad rights to the **source code**:
use, copy, modify, merge, publish, distribute, sublicense, and sell.

It does **not** grant any rights to the project's **name or branding**. Under
trademark law these are distinct: copyright covers the expression (the code),
trademark covers source identification (the name). An open-source license on
code never grants trademark rights — this is true of MIT, Apache-2.0, and every
OSI-approved license.

## What you may do

- Fork the code and use it privately, internally, or commercially.
- Modify it, including for a competing or derivative product.
- State factually that your project "is based on novel-harness" or "is a fork
  of novel-harness".
- Redistribute a fork under your **own** name and branding.

## What you may not do

- Call your fork or derivative "novel-harness", or name a redistributed `novel`
  binary such that it appears to be this project.
- Use the name or logo in a way that implies endorsement, affiliation, or
  official status.
- Present a hosted service as the official novel-harness service.

## Why this is the policy

Restricting the *name* protects users from confusion about who maintains the
software they run, without restricting the *code*. It keeps the project
genuinely open while making it clear that the branding identifies this project.

## A fork's obligations

A fork that uses the name in a factual, non-endorsing way must still keep the
upstream copyright notice (required by MIT) and must make clear it is not the
official project.
